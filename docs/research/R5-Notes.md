## Main Topic - Production Planning, API Standards, and UI Components

This week's research focuses on planning for production by creating structured backend APIs, organizing project tasks using GitHub Issues, and breaking down user interfaces into manageable component hierarchies. These concepts help me transform my design blueprints into an organized coding workflow.

### Core Architectural Concepts & Best Practices

* **REST API Design Best Practices:** I learned that building an excellent API means keeping endpoints clean and logical. Using clear HTTP methods (like GET for retrieving data and POST for creating items), using plural nouns for routes, and returning standard JSON status codes are essential steps. Keeping my API structured this way ensures my frontend can fetch data without unexpected errors.
* **Tracking Work with GitHub Issues:** I reviewed how to use GitHub Issues as a living project plan rather than just a basic to-do list. Using clear titles, descriptive breakdowns, labels, milestones, and project boards helps clarify project scope. This habit makes it easy to organize major development goals into small, trackable steps before writing code.
* **Atomic Web Design Fundamentals:** I studied the concept of breaking a webpage down into small, reusable building blocks. Instead of viewing a user interface as a single large screen, I need to look at it as a combination of atoms (like buttons and inputs), molecules (like a search bar form), and organisms (like a complete navigation header) to keep my project clean.
* **Component Hierarchies in React:** I learned how to break down an interface into structural parent and child trees. By mapping out a visual layout into separate components before building it, I can see exactly where my application data needs to flow, which helps me avoid messy code duplication.
